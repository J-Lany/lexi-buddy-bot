# Telegram UI: screen-mode vs chat-mode

В боте есть два режима вывода сообщений:

## 1) Screen mode (навигация по меню)

Используем, когда пользователь “гуляет” по меню: Home / Lessons / Lesson / Profile / Help.

**Правило:** экран — это _одно_ сообщение, которое мы переиспользуем (редактируем).

- Рендер: `safeEditScreen(...)`
- Состояние: `ctx.session.ui.screenMessageId`

Зачем:

- интерфейс выглядит как “приложение”
- не засоряем чат сотней одинаковых сообщений меню

## 2) Chat mode (прохождение задания)

Используем внутри прохождения конкретного задания (assignment run).

**Правило:** каждое состояние/шаг/фидбек — _новое_ сообщение.

- Рендер: `sendChat(...)`
- Ничего не редактируем, чтобы:
  - сохранялась история вопросов
  - ответы пользователя не “уезжали” ниже экрана из-за редактирования предыдущего сообщения

---

# Переходы между режимами

## Из Screen mode в Chat mode

Когда пользователь открывает задание:

- начинаем новый run (`clearAssignmentRun(ctx)`)
- начинаем показывать шаги через `sendChat(...)`

## Из Chat mode обратно в Screen mode (важно!)

Если пользователь закончил задание или ушёл в меню/профиль/уроки,
нельзя продолжать редактировать старое “assignment сообщение”.

**Правило:** при выходе из assignment-экранов нужно начать новый screen.

Для этого используем:

- `beginNewScreen(ctx)` — сбрасывает `screenMessageId`
- `ensureScreenMode(ctx, nextScreen)` — если уходим из assignment → вызывает `beginNewScreen`

---

# Рекомендованный паттерн в routes

В любых местах, где навигация может увести пользователя
из assignment в обычные экраны (home/lessons/profile/help/back),
вызываем:

- `ensureScreenMode(ctx, nextScreen)`
- `clearAssignmentRun(ctx)` (если реально выходим из assignment)

Так мы гарантируем:

- assignment идёт как чат-история
- меню работает через edit одного сообщения
